# Review guide

VOIDFORGE is meant to be read. The security-relevant code is a few hundred lines in `voidforge.html`. Find each part by its function names below (search the file for them); line numbers change with every release, so they are not given.

| What | Where | Look for |
|---|---|---|
| BIP39 wordlist | line | Any changed word. The self-test hashes it against the official `english.txt` (`2f5eed53...dbda`); verify that hash yourself. |
| Roll to mnemonic | `rollsToMnemonic`, `entropyToMnemonic` | Entropy truncation, checksum bits, anything that mixes in other data (time, `Math.random`). |
| Input cleaning | `clean` | Anything that alters or drops valid input. |
| Fingerprint | `ripemd160`, `eadd`/`emul`, `mnemonicToSeed`, `fingerprintFromSeed` | Correctness only; it does not affect the seed. Not constant-time (offline use). |
| First receive address | `masterFromSeed`, `ckdPriv`, `bech32Encode`, `firstAddressFromSeed` (search these names) | Display only; it does not affect the seed. Check the derivation path (`m/84'/0'/0'/0/0`: 84, 0, 0 hardened, then 0, 0), the mod-n key addition, and that the bech32 checksum constant is 1 (BIP173). Tested against the published BIP84 vector and two independent libraries. |
| SeedQR input, BIP85 child seeds and other BIP85 outputs | `phraseFromCode`, `checkPhrase`, `bip85Entropy`, `bip85Mnemonic`, `bip85App`, `mnemonicBip85`, `mnemonicBip85App`, `deriveChild`, `deriveChildApp`, `keccakF`, `shake256Reader`, `base85Encode` | SeedQR/CompactSeedQR are only a different way to type the same words in; the result goes through the normal checksum check. BIP85 reads the parent's private key to make a new secret seed (HMAC-SHA512 of the key at m/83696968'/39'/0'/{words}'/{index}'), so it is as sensitive as the parent: shown on screen, and printed only after PRINT CHILD SEED asks for confirmation; never copied or saved. Self-test checks nine published BIP85 vectors and the SHAKE256 vector; the oracle test compares 135 children with @scure and Node's HMAC. |
| Reforge (seed and passphrase recovery) | `reforgeParseWords`, `reforgeChecksumOk`, `reforgePlan`, `reforgeTarget`, `reforgeBech32Ok`, `reforgeMatch`, `reforgeSearch`, `reforgePassCandidates`, `reforgePassSearch`, `reforgeWords`, `reforgePassphrase`, `lastWordCandidates` | Handles secrets (typed words and passphrase guesses) but only reads them, never stores or sends them; CLEAR and any edit wipe the result. See the note below. |
| Read-only PSBT and raw-transaction inspector, checks and verdict | `inspectPsbt`, `inspectRawTx`, `psbtParseTx`, `psbtAddress`, `psbtChecks`, `psbtVerdict`, `psbtReport`, `opReturnText` | Parses BIP174 version 0 and BIP370 version 2 and displays them. No signing, no key use, no network; checked against @scure/btc-signer for every address type, and by about 38 mutations. |
| Tabs, seed panel, word slots (display only) | `showTab`, `reveal`, `renderSlots`, `updateSeedPanel` | v1.25.0 moved the page into tabs. These functions only show/hide sections and draw the counter and empty slots; they never read or change the seed. Tests check that every control still exists inside a tab. |
| Fairness test, Word finder (display only) | `faceTest`, `wdFindWord` | Chi-square p-values use exact formulas for 1 and 5 degrees of freedom (checked against scipy). The Word finder only indexes the BIP39 list; it never touches the seed. |
| Signature checks (nonce reuse, sighash) | `sigDer`, `sigSchnorr`, `scriptPushes`, `sigsFromScriptSig`, `sigsFromWitness`, `nonceReuse`, `sighashName`, `sighashOdd`, and the two signature checks in `psbtChecks` and `compareTx` | Read-only, public data only: it never verifies or makes a signature, it only reads R values and sighash bytes. Check that DER parsing is strict (damaged encodings are ignored, not guessed at), that identical signatures are not called reuse, and that only the taproot key-path witness form is read as Schnorr. Limit: reuse is found only inside the transaction (or the two in the compare box) you paste in, not across the whole blockchain. `tests/oracle.test.mjs` builds real signatures with @noble/@scure and proves a repeated nonce leaks the key. |
| Compare two transactions (signer-change and fee-bump checks) | `compareTx`, `runCompare` | Read-only. Reports every difference between two transactions; calls a replacement a plain fee bump only when it spends a shared coin, the first allows RBF, the fee is higher, and no one who was paid is paid differently (except the change). Checked against transactions built by @scure/btc-signer. |
| Backup practice mode | `practiceMake`, `practiceCompare`, `practiceStart`, `practiceHide`, `practicePeek`, `practiceCheck`, `practiceClear` | Display only, and the phrase is one of the published BIP39 test phrases (`PRACTICE_ENTROPY`), never your seed. Check that it is not derived from anything you typed and that `practiceClear` forgets it. Word positions are checked against @scure in `tests/oracle.test.mjs`. |
| Start notice, privacy box, END SESSION | `startGateClose`, `startGateSkip`, `ackSeen`, `ackRemember`, `endSession`, `#startGate`, `#privacyBox` | Display only. The notice must close with one click or Escape and must not touch the seed. It is skipped only when the browser is offline and this tab's session storage holds `voidforge-ack` = "1"; closing it stores that flag only while offline (nothing else is stored there, and nothing at all online). END SESSION wipes everything, resets every box to its default, deletes that flag and reloads. The privacy box makes claims you can check: only `voidforge-theme` and `voidforge-big` are kept between visits (local storage), the session flag dies with the tab, and there are no network calls. |
| Compare key/descriptor, address finder | `classifyRecorded`, `parseDescriptor`, `matchRecorded`, `walletIds`, `findAddress`, `checkAddress` | Display only; no secret leaves the page. Inputs are public data (zpub/xpub, descriptor, addresses). The comparison is exact string equality with keys the page derives itself; the descriptor checksum is verified. The finder re-derives addresses with the same functions the self-test checks. Covered by end-to-end probes against independent libraries and 28 new mutations. |
| Taproot addresses (BIP86) | `taggedHash`, `taprootAddress`, `taprootAddressesFromSeed`, `bech32Encode` (bech32m constant) | Display only, public data. Key-path only (no script tree): output key = internal key + SHA256-tagged TapTweak. Self-test checks the three published BIP86 vectors and the BIP350 example; the oracle test compares 150 addresses with @scure/@noble. |
| First 10 receive and 10 change addresses, roll chart, 4-letter view | `walletAddresses`, `showAddrs`, `renderRollChart`, `toggleAbbr` | Display only. The addresses are public data derived the same way as the first address (m/84'/0'/0'/0/0 to 0/9 and 1/0 to 1/9, and the same for Taproot at m/86'). The chart and the 4-letter view are built with `textContent`/DOM nodes, no `innerHTML`, and never touch the seed. |
| Watch-only export | `watchOnlyFromSeed`, `base58check`, `descriptorChecksum` | Public data only: check that no private key or seed byte is ever serialized (version bytes 0x0488B21E / 0x04B24746 are public-key versions; the key placed in the output is `pubkeyBytes(k)`), depth 3, hardened index 0x80000000, parent fingerprint. Tested against the published BIP84 zpub, @scure/bip32 on random phrases, and embit-generated descriptors with checksums (`tests/fixtures/watchonly.json`). |
| QR codes, SeedQR | `qrBuild`, `qrMatrix`, `seedQrData`, `seedQrMatrix`, `qrSvg`, `showQr`, `showSeedQr` | Public-data QR codes: byte mode, error correction M, versions 1-30. SeedQR (secret, on request only, never stored): numeric mode / CompactSeedQR byte mode, error correction L, versions 1-3, printing needs confirmation. Matrices checked bit for bit against Python `qrcode`; drawn as inline SVG (no library, no network). Tested bit for bit against the independent `qrcode` library for every version and mask (`tests/fixtures/qr.json`), and the same matrices were decoded with zxing-cpp and OpenCV. The automatic mask choice can differ from other libraries (any mask is valid). |
| Seed explainer, printed backup sheet | `explainSteps`, `showExplain`, `hideExplain`, `printSeed` | Display only. `explainSteps` repeats the FORGE math as an independent cross-check and `showExplain` refuses to claim a match unless it reproduces the real words; it shows secret numbers (marked SECRET, closed by default, cleared by `setResult`) and never the passphrase. Printing asks for confirmation and never includes the passphrase. |
| Guide me, term tips, text size | `toggleGuide`, `guideStep`, `guideRender`, `guideCanNext`, `toggleSize`, `.term` handlers | Display only. They show or hide existing elements with a CSS class and never read, change or store seed material (the only browser storage is the theme and text-size choice, plus the start-notice flag for one tab while offline). `guideCanNext` only gates the NEXT button; it does not gate FORGE. |
| Live preview (display only) | `previewRefresh`, `previewClear`, `rollsToMnemonic` | Display only. The gray preview words are `rollsToMnemonic` of the rolls so far, the same function FORGE SEED uses, shown in the word boxes with a PREVIEW note. They must clear on FORGE, CLEAR and an empty roll box, and never be printed, saved or copied as a seed. |
| Wallet view, address QR, recovery sheet | `openWalletView`, `walletAddresses`, `wvRefresh`, `wvPage`, `wvSeedQr`, `clearWalletView`, `addrLi`, `showAddrQr`, `printRecoverySheet` | Any valid 12 to 24 word phrase from the Check tab. Public addresses only, except SeedQR (secret, 12 and 24 words only). Check the derivation path `m/purpose'/coin'/account'/chain/index`, that editing the words wipes the view, and that the recovery sheet never contains words or the passphrase. Tests compare every address type, network, account and chain with independent libraries and read every QR back with jsQR. |
| Account finder, roll and stamp sheets, auto-clear | `checkAllAccounts`, `printRollSheet`, `printStamp`, `autoClearSet` | Display and print only. The account finder reuses `findAddress`; the sheets print only what is already on screen (the stamp sheet has the first four letters of each word, never the passphrase); auto-clear is off at load and stores nothing. |
| Watch-only view, payment request, Electrum warning, checklist, key-reuse check | `parseWatchInput`, `openWatchOnly`, `watchAddresses`, `addressFromPub`, `taprootAddressFromPoint`, `bip21Amount`, `bip21Uri`, `drawAddrQr`, `electrumSeedType`, `electrumNote`, `bkUpdate`, `bkReset`, `bkTick`, `descriptorKeyList`, `keyReuseReport` | Public data only. Check that `parseWatchInput` and `keyReuseReport` refuse private keys, that watch-only derivation is public (`ckdPub`) and non-hardened only, that the BIP21 amount is at most 8 decimals, above 0 and at most 21 million, and that the Electrum check only adds a note to a phrase BIP39 already rejected. The checklist only ticks boxes on the page. |
| Multisig | `base58decode`, `parseExtendedKey`, `ckdPub`, `multisigScript`, `multisigAddress`, `multisigDescriptor`, `msAddMade`, `msAddPasted`, `wipeSeed` | Public data only: the page keeps public keys and fingerprints, never a seed, after ADD. Keys are checked (checksum, curve point, version, depth, path, network), private keys are refused, pubkeys are sorted (BIP67), addresses are tested against @scure/btc-signer and descriptors against embit. `wipeSeed` clears the page state; JavaScript cannot guarantee memory is zeroed, which the page says. |
| Silent Payment address, Core import text | `bech32mText`, `spEncode`, `spAddressFromSeed`, `coreImportText` | Public data only. The address is bech32m of version 0 plus the scan and spend public keys from `m/352'/coin'/account'/{1'\|0'}/0`, checked against all official BIP352 vectors and `@scure/bip32`. The Core text only wraps public descriptors in `createwallet`/`importdescriptors` and is labeled a template. |
| Word draw | `wdResolve`, `wdParse`, `wdSteps`, `wdGenerate`, `finishSeed` | The entropy is the typed words' 11-bit numbers plus the typed flips, packed into bytes with no hashing; the checksum is the first bits of SHA-256 of those bytes (standard BIP39). `wdSteps` rebuilds the mnemonic with `entropyToMnemonic` and checks that the typed words come back as the first words. Checked against `@scure/bip39` on 100 random draws and against the all-zero and `7f` known vectors. Flips are never defaulted; all-same flips and identical or alphabetical words only ask for confirmation, because refusing them would bias the result. |
| Fingerprint picture | `lifeHash`, `lifeHashSvg`, `lhGradient` | Display only (it receives the 8-hex fingerprint, nothing else). LifeHash version 2 (Blockchain Commons): SHA-256 of the 4 fingerprint bytes, a Game of Life run, gradient and mirror pattern. Tested pixel for pixel against the independent `lifehash` npm package (150+ random fingerprints) and against the real picture Sparrow Wallet shows for fingerprint 4fbf7566 (`tests/fixtures/sparrow_4fbf7566.json`). Other LifeHash ports (a Python one, another JavaScript one) disagree with it on a few fingerprints; see the note below. |
| Result display | `setResult`, `hasSeed` | `setResult` is the only place that sets the result area; `hasSeed()` (a flag set only when a real seed is showing) guards SEND TO CHECK, PRINT and DOWNLOAD so an error message is never treated as a seed. The word grid is display only. |
| Roll count, Keystone dice rules (v2.3.0) | `generate`, `getNeeded`, `countNote`, `keystoneOn`, `hashInput`, `rollsToMnemonic` | FORGE needs at least the minimum (50/99 dice, 128/256 flips) and hashes every roll typed in. Keystone rules: each 6 becomes 0 before SHA-256, at least 50/100 and at most 256 rolls; the rules are part of the stale-result signature, so changing them clears the words. Self-test vectors from an independent Python BIP39; oracle checks random lengths with `@scure/bip39`. |
| BitBox02 diceware (v2.3.0) | `wdFindWord`, `wdAddFound`, `wdBitBoxHint`, `wdSteps`, `inputSig` | The table code d1 d2 d3 d4 d5 H/T maps to word number (((d1-1)*64+(d2-1)*16+(d3-1)*4+(d4-1))*8)+(d5-1)*2+(T?1:0), the order of BitBox's printed table. The 24th word is standard BIP39 (Word draw with 3 flips, T = 1); self-test uses BitBox's own firmware test vector (23 x violin). A Word draw seed is cleared when its words, flips or length change afterwards (the inputs are part of the stale-result signature). |
| Verify a signed message (v2.3.0) | `verifyMessage`, `sigCheckOnce`, `msgHashLegacy`, `ecRecover`, `ecdsaVerify`, `schnorrVerify`, `bip322Parts`, `bip322SighashWpkh`, `bip322SighashTr`, `derParse`, `witnessParse`, `segwitDecode`, `sigArmor` | Read only; it never signs and never touches a seed. Classic (BIP137): public key recovery from the 65-byte signature, then the address of the type typed in must match. BIP322 simple: P2WPKH (BIP143 hash, strict DER, low S, SIGHASH_ALL) and P2TR key path (BIP341 hash, BIP340 Schnorr, DEFAULT or ALL). Multisig, script paths and full signatures give CANNOT CHECK. If the exact text fails, it tries the text with Windows line breaks either way, with spaces and line breaks trimmed from its ends, and with a final line break added, and says so (in amber) when only such a variant matches. VALID always names the address it checked, and a pasted signed-message block can never replace an address or signature you typed. Unprefixed BIP322 full signatures (a whole transaction or PSBT) say CANNOT CHECK. Checked against every official BIP322 vector (tests/fixtures/bip322-*.json, with and without prefixes), Bitcoin Core's test vector, a recovery-id-2 vector, and signatures made by `@noble/curves` and `@scure/btc-signer`. |
| Prints (v2.4.0) | `printSheet`, `printSrc`, `sqSrc`, `printSeed`, `printStamp`, `printSeedQr`, `printSqGuide`, `printSqBlank`, `printShownQr`, `printAddrQr`, `printChild`, `printWordSheet`, `printSummary`, `rsExtraCount`, the `@media print` rules | Every sheet prints on exactly one page (Letter and A4): everything but the print area is `display: none` while printing. `tests/print.test.mjs` prints every sheet to PDF in Chromium and counts the pages. Secret sheets ask first and say so; the passphrase is never printed; print areas are wiped after printing. A QR sheet describes the code that was on screen when SHOW QR was pressed, and changing the type, network or account hides that code. |
| Typo helper, Explain an address (v2.4.0) | `wordFromPrefix`, `wordDistance`, `closestWords`, `checkPhrase`, `explainAddress`, `dictGo` | 4 or more letters that start one BIP39 word are read as that word (the checksum still decides); unknown words get suggestions only, nothing is changed. Addresses are decoded (bech32/bech32m with a re-encode check, Base58Check) and described; nothing is sent anywhere. |
| Dice test (v2.4.0) | `diceTestOn`, `diceTestToggle`, `diceTestText`, `generate` | While the test is on, FORGE is off and refuses, no words are previewed, and starting or ending the test clears the rolls, so test rolls never become a seed. |
| Backup plan, stress test, wallet birthday (v2.5.0) | `planState`, `planStress`, `planRender`, `planSecret`, `printPlan`, `planFill`, `todayISO`, `plusYearISO` | No secrets: the plan holds places, people and how the passphrase is kept. Before printing, `planSecret` checks all boxes together and refuses 12+ seed words in a row (also 4-letter forms, one misspelled word, labels such as w1 skipped), SeedQR digits or hex (also in groups), "passphrase:" or "password:" followed by text, and keys or private descriptors (base58 or descriptor tokens that `explainAddress` calls PRIVATE). The stress test is a fixed rule table for a single-key wallet; check each verdict. The birthday is the local date at FORGE. |
| Practice mode, watch-only file (v2.5.0) | `practiceMode`, `shownFirstAddress`, `reshowSeed`, `isPracticePhrase`, `watchFileText`, `saveWatchFile` | Practice mode switches and locks the network menus (`wNet`, `wvNet`, `psbtNet`, `cmpNet`, `msNet`) and shows every address view on the test network (first address, address lists, watch-only box, Open this wallet, VERIFY lines, child seed); it refuses to change while a multisig wallet exists, and seed words are unchanged. Mainnet watch-only keys are refused while it is on. VERIFY names the public practice phrases. The watch-only file is written from a snapshot of the finished refresh, holds public keys only, and its one non-comment line is the BIP389 multipath descriptor with its checksum; not offered for a multisig cosigner key. |
| Passphrase warning, secrets not selectable (v2.5.0) | `passHiddenNote`, `passWarnUpdate` | Checked after NFKD (as BIP39 does): spaces at either end, double spaces, invisible (format) characters, tabs and line breaks; never changes the passphrase. Seed words (also the hidden copy in `#genResult`), the 4-letter grid, child outputs, Reforge results and the explainer have `user-select: none`. |
| UR, BBQr and animated QR (v2.6.0) | `crc32`, `bytewordsMin`, `bytewordsMinDecode`, `cborHead`, `CB`, `cborRead`, `urFragLen`, `urEncode`, `urDecodeFrames`, `base32Encode`, `base32Decode`, `bbqrEncode`, `bbqrDecodeFrames`, `inflateRaw`, `qrTextDecode`, `cryptoOutputMultisig`, `coldcardMultisigText`, `animStart`, `msAnim` | Written from BCR-2020-005 (UR), BCR-2020-012 (Bytewords), BCR-2020-010 (crypto-output) and bbqr.org. The page's own encoder writes only the pure parts 1..n (no fountain mixing); the page's own decoder reads single and pure parts, leaves out mixed parts, and checks every CRC. (The practice signer has its own decoder, which does read fountain-mixed parts: see the practice signer row.) Frames are upper case in QR alphanumeric mode, all at the version of the longest part. The inflater is for BBQr Z parts only (output limited to 4 MB). Public data only: descriptors, setup files and PSBTs. `tests/oracle.test.mjs` compares the UR parts byte for byte with `@ngraveio/bc-ur`, reads the crypto-output back with `@keystonehq/bc-ur-registry` and checks BBQr both ways with `bbqr`. |
| PSBT pasted as animated-QR text (v2.6.0) | `psbtFromText` | UR crypto-psbt (also psbt and bytes) and BBQr P, T or U parts, one per line; the other formats (base64, hex) are unchanged. A BBQr U part that holds QR text again is not read a second time. |
| Custom path, private key read only (v2.6.0) | `parsePath`, `walletAddressesFrom`, `parsePrivateInput`, `pubOfPriv`, `openPrivateKey`, `wvRefreshSingle` | Read only: nothing is signed or sent. xprv-type keys at depth 0 work like a seed, deeper ones like an account key; WIF and mini keys show the addresses one key can have. | Check an address before you pay, spending cost (v2.6.0) | `payNorm`, `payCompare`, `costEstimate`, `costUpdate` | The pay check compares every character (bech32 ignores case, Base58 does not) and warns when at least 3 leading and 3 trailing characters match but the middle does not. **BIP85 outputs (v1.29.0):** `bip85App` makes the BIP85 applications other than seed words, from the same 64 bytes (`bip85Entropy`: HMAC-SHA512 keyed "bip-entropy-from-k" over the key at `m/83696968'/app'/...`, every step hardened). WIF (app 2): the first 32 bytes, compressed, mainnet. XPRV (app 32): BIP85 puts the chain code first and the key second, the reverse of BIP32, with depth, parent fingerprint and child number 0. HEX (128169), Base64 (707764) and Base85 (707785, RFC 1924 alphabet) passwords take the length as a path number and slice the output. Dice (89101) read a SHAKE256 stream of the entropy (`shake256Reader`, a plain Keccak-f[1600] on BigInt lanes), take ceil(log2(sides)) top bits per roll and skip values at or above the number of sides; sides are limited to 2^31 - 1 because they are a hardened path number. Check the byte order of the XPRV, the padding byte (0x1f is SHAKE, 0x06 would be SHA3) and the rate (136 bytes for SHAKE256). Every application is a self-test vector from the BIP, and the tests compare all of them with @scure/bip32 and Node's SHAKE256.

**Reforge (v1.28.0):** the words search runs in two steps. `reforgePlan` picks one fixed plan from what was typed (fill 1-2 `?` words; all words typed: the phrase, every swap of two different words, every single word replaced; one word short: the missing word at every place, with the n duplicate phrases skipped) and `reforgeChecksumOk` keeps exactly the phrases with a valid BIP39 checksum. Then each one is stretched with the typed passphrase (`mnemonicToSeed`) and compared by `reforgeMatch` with the check value: a master fingerprint (32 bits, so matches are reported with their coincidence odds and the search never stops early), an address (receive 0 to 9 of account 0; the address's own bech32/bech32m or Base58Check checksum is verified first, so a typo is refused instead of wasting a long search), or an account xpub/ypub/zpub/tpub/upub/vpub at depth 3 (compares the chain code after the hardened path, then the public key). Address and key matches end the search. Things to check: that no plan can drop a candidate (the tests compare every plan with an independent enumeration and @scure's `validateMnemonic`), that `reforgeMatch` derives the documented paths, that "FOUND" is only said for a real match, and that a stopped search is never reported as complete. The passphrase search (`reforgePassCandidates`, `reforgePassSearch`) tries no passphrase first, then each line, ordered pairs and triples of different lines (joined with nothing or a space), in typed/lower/UPPER/Capitalised form (and trimmed), and with the box ticked one typo per guess (a character left out, doubled, swapped with the next, or in the other case); lines are kept exactly, and more than 1,000,000 guesses are refused before starting. Runs on the page's main thread in chunks (`reforgeYield`, MessageChannel so a background tab is not throttled), because the Content-Security-Policy rightly blocks workers. `ckdPriv` takes an optional precomputed parent public key, used only for non-hardened steps.

**Restore drill (v1.27.0):** `drillStart`, `drillCheck` and `drillEnd` compare what you type with the words and passphrase held for the current seed (`watchCtx`, the same copy the watch-only box uses). The words are hidden by CSS only (`body.drill-on`): they stay in the page, so it protects against looking, not against anyone who can read the page. The page reports positions, never the right words, and compares the passphrase after Unicode normalization (NFKD), like the seed derivation. The drill ends whenever the result changes (`setResult` calls `drillEnd`), which also wipes what you typed. It uses no storage and no network.

**Check your download (v1.27.3):** `dlCheck`, `dlCid`, `dlParse`, `dlPick`, `dlClear` hash the chosen file with the browser's own SHA-256 and compute a CIDv1 (raw, sha2-256, multibase prefix bytes `[1,0x55,0x12,0x20]`), then compare both against whatever the user pastes (a bare hash, upper case, a full `SHA256SUMS` line, a CID, or several values together; every value present must match for a MATCH verdict). The chosen file is read with `FileReader` only, never uploaded, stored or sent. `dlCid`'s length check (`w.length === 59`) matters: a loosened check would accept a truncated CID as real, so there is a dedicated regression test pasting a truncated CID and asserting it reports `none`, not a false match. Know the limit: a tampered copy of the page could lie about its own hash, which is why the page itself says to also check with `sha256sum` from another tool.

**Support this project / Bitcoin dictionary (v1.27.3):** `drawSupportQr`, `copySupport`, `buildDict`, `dictFilter` are both display-only with no secret-adjacent data; nothing here reads the seed or sends anything over the network (the Lightning QR is drawn from a fixed, published text value; the dictionary is a static array filtered client-side). Worth checking only for the honesty of the claims made in the UI text, and that the BIP/SLIP-coverage test (`tests/test.js`) still fails if the page names a standard the dictionary lacks an entry for.

**Stale-result guard (v1.26.1):** `inputSig`, `staleCheck` and `seedSig` record the inputs (rolls, word count, mode, both passphrases) at the moment of FORGE. If any of them changes afterwards, the words, fingerprint, address and watch-only data are cleared, so what is on screen (and what DOWNLOAD saves) always belongs to the inputs that made it. A Word draw seed depends on the passphrase only. The saved file uses the rolls remembered from FORGE, not whatever is in the box now. **Run counter (v1.29.1):** `forgeRun` moves on at every FORGE (`finishSeed`), every clearing by `staleCheck` and every `wipeSeed` (CLEAR ALL). `finishSeed` checks it after each `await` (fingerprint, first address, address list, watch-only data) and stops if it has moved, so an older run that is still working out its fingerprint and addresses can never write them back after you changed an input or cleared the page.

Tests worth reading too: `tests/oracle.test.mjs` compares the seed math with `@scure` on random inputs, and `tests/mutation.test.mjs` shows which deliberate breaks the in-page self-test catches and which only the CI probe catches.

Independent checks anyone can run: compare with SeedSigner's `tools/mnemonic.py`, or Ian Coleman's BIP39 tool run offline ("Base 10"/"Hex" mode for dice, "Binary" for coin flips).

Known limits: the randomness meter only catches lazy input; the curve code is not constant-time; coin-mode test vectors come from an independent implementation of SeedSigner's method (SeedSigner publishes none); the dice check is compared with SeedSigner's, Coldcard's and Keystone's own dice code (`tests/vendor.test.mjs`), not with the devices themselves; the full suite runs in Chromium, and a shorter check runs in Firefox and WebKit (`tests/browsers.test.mjs`), not in Safari itself.

## Note on the fingerprint picture (LifeHash)

The picture is LifeHash version 2 of SHA-256 of the 4 raw fingerprint bytes, which is what Sparrow Wallet shows. It was checked against the real Sparrow picture for fingerprint `4fbf7566` pixel for pixel (fixture in `tests/fixtures/`), and by eye against Sparrow for three more wallets covering the other gradient families. It matches the `lifehash` npm package on every fingerprint tested. Two other LifeHash ports I tried disagree with it on some fingerprints (a PyPI package on some triadic gradients; an npm `@bcts/lifehash` beta on a few pixels in about 1% of cases); since the picture only has to match Sparrow's and the results above match, those ports were treated as outliers. The picture is display only and never affects keys or addresses; the 8-character fingerprint is the real check.
